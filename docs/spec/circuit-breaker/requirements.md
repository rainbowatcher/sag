# 熔断器 — 需求

## 目标

当上游持续返回错误时，暂时跳过问题 target，避免浪费重试资源，给上游恢复时间。

## 预期行为

### 错误分类

上游错误按 response body 关键词分为三类：

| 冷却类型 | 触发条件 | 默认冷却 |
|---------|---------|---------|
| 额度耗尽 | HTTP 429 + body 含 quota/billing 关键词 | 3600s (1h) |
| 速率限制 | HTTP 429（非额度相关） | 10s |
| 通用故障 | 5xx / 网络超时 / 连接错误 | 60s |

分类逻辑：先精确匹配 `"rate limit"` → `RateLimited`，再匹配 quota/billing 关键词 → `QuotaExhausted`，其余 429 和 5xx/网络错误 → `Generic`。

### 冷却行为

- 目标重试耗尽后 → 按错误类型打开对应冷却时长的熔断器
- 冷却期内 → 目标在路由选择时被跳过（视为不可用）
- 冷却期结束 → 目标自动重新加入路由
  - StickyFailover：继续优先使用 sticky target
  - FillFirst：按优先级尝试首选
  - RoundRobin：回到轮转顺序

### 无请求时自动关闭

冷却期是时间驱动的，不需要请求触发。冷却时间到后目标自动可用。

## 配置 Schema

```toml
[circuit_breaker]
quota_exhausted_secs = 3600   # 默认 1h
rate_limited_secs = 10        # 默认 10s
generic_secs = 60             # 默认 60s
```

## 功能边界

### 包含
- 按错误类型分类
- 时间驱动的冷却
- 自动恢复

### 不包含
- 半开状态（half-open）探测
- 滑动窗口计数
- 基于成功率的熔断（仅时间驱动）

## 与其它模块的交互

- **路由**：检查目标的熔断器状态
- **调度**：重试耗尽后打开熔断器
